# 环与行星的亮度尺度：量测、订正与修法

问题：环的着色器把自己的反射率（I/F）直接写进片元颜色，而行星走 three 的标准路径
（`albedo/π × 光强 × N·L`）。两者是不是在同一个亮度尺度上，差多少？结论是环一度比物理暗约四成，
原因在抗锯齿的撑宽上，已修；下面的量测是修前修后的依据。

## 量测方法：以关闭色调映射的一帧为地面真值

渲染器的 ACES + 曝光会压缩比值，**反解它不如绕开它**：把 `renderer.toneMapping` 临时设为
`NoToneMapping` 渲染一帧，屏幕值就等于场景辐射本身，中间只剩 sRGB 传输函数。
本目录的绝对数字一律来自这种帧（`NO_TONE=1` 读），比值因为两边同源，受曲线影响较小。

```bash
npm run dev
TAG=default2026 node shoot.mjs                     # 默认取景 + 一份几何/光照快照
TAG=default2026 OFFSET='[...]' node shoot.mjs      # 也能指定相机偏移（两极取景用）
NO_TONE=1 npx tsx photometry.mjs default2026       # 读关掉色调映射的那一帧
```

采样要剔除两类像素，否则会把行星的亮度记到环上：被行星挡住的环面，以及盘内那些
「透过薄环看到的行星」（不剔除时读出来的 C 环比 B 环还亮）。

## 两处必须做对的地方

1. **I/F 的定义**：I/F = πL/E，所以朗伯面的 I/F = `albedo × mu0`，**不是** `albedo × mu0 / π`。
   环的反射率表用的也是这个约定（守恒厚层的法向入射反射率 ≈ 1.0，见
   `ring-multiple-scattering.test.js` 对 Chandrasekhar 公布值的校核）。
2. **行星盘的反照率**：按每个像素的经纬度去读它真正渲染的那张贴图，不能用整图均值——
   这个视角看到的是明亮赤道带，逐像素实测 0.70，整图均值只有 0.55。取贴图时注意 three 的球面
   UV 是 `u = atan2(z, -x)/2π`，且要用**网格本地**方向（先乘 attitude 的逆）。

## 结论

### 一、环相对行星：差 1.7 倍，原因在撑宽

关掉色调映射的一帧里（2026-09-15 默认取景）：

| 表面 | 屏幕辐射（原始线性） | 模型 I/F | screen/I-F |
| --- | --- | --- | --- |
| 行星盘 | 4.17e-1 | 5.78e-1 | 0.722 |
| B 环（现状修正前） | 4.07e-2 | 9.68e-2 | 0.421 |
| B 环（`RING_MIN_PIXELS=0`） | 7.16e-2 | 9.68e-2 | 0.740 |

行星盘按最朴素的朗伯模型应当是 `albedo/π × 2.6 × mu0 = 4.73e-1`，实测 4.17e-1，相差 12%——它是准的。
环则只有物理值的 0.58 倍；把亚像素撑宽关掉，环回到 1.03 倍。**撑宽让整条环带丢了约 43% 的光**：
相邻环带各自对称撑到 1.5 像素后重叠，而半透明 over 合成的 alpha 小于各自之和
（`a₁+a₂−a₁a₂ < a₁+a₂`），每条按自己撑宽倍数压掉的光没有被加回去。

**修法**：`createRingSystemGeometry` 给每条环带的每条边写一个 `aRingRoom`（该边到相邻环带中点的一半
距离，环系两端不设限），顶点着色器把撑宽量取 `min(撑宽, aRingRoom)`。贴合的环带不再撑宽
（土星那 401 条彼此贴合，整条带远宽于一个像素，不会漏采样），孤立的细环照旧撑到 1.5 像素
（天王星要的就是这个）。修后同一帧：B 环 screen/I-F 0.740、相对行星 **1.03 倍**；
天王星专项读数不变（斑点指数 1.288、34% 行无凹陷）。

### 二、环的两个面

2002 至点、相机放在极轴 11 倍半径正对环面，两个面各拍一张：

| | 屏幕（原始线性） | 模型 I/F | screen/I-F |
| --- | --- | --- | --- |
| 受光面 B | 5.66e-2 | 8.03e-2 | 0.705 |
| 背光面 B | 7.69e-3 | 1.41e-2 | 0.548 |
| 受光面 A | 1.52e-2 | 4.65e-2 | 0.328 |
| 背光面 A | 8.98e-3 | 2.31e-2 | 0.389 |

背光面/受光面：屏幕上 B 环 13.6%、A 环 58.9%；模型给 17.5% 与 49.6%。即背光面的相对亮度落在
物理值的 **0.78 倍**与 **1.19 倍**——方向、厚薄顺序都对，量级在量测自身的不确定度之内
（带状平均、24 角表插值、逐带覆盖度），但没有精确到几个百分点。

- 物理上正确的部分：哪一面被照亮（纯几何）、两面共用同一套粒子颜色、背光面走透射解、
  行星投在环上的影同时压暗两面、冲效应只加在反射面（它是按反射 I/F 拟合的测量量）。
- 没建模的：透射方向的相干前向峰；环的垂直结构；以及透射解本身的秩二截断残差
  （tau ≤ 1 的环区 16% 以内，厚的环区绝对值不超过受光面的 12%）。
- 屏幕与线性还有一层差别：ACES 的趾部会把背光面压得更暗，同一取景 B 环的背光/受光
  线性是 13.6%、屏幕上是 6.5%——**看到的反差比线性物理更大**。
- C 环两面都不采信：像素只有 0.7–1/255，读的是噪声。

### 三、显示亮度是一个具名系数

`dynamics.js` 的 `RING_DISPLAY_LEVEL`（当前 0.85）乘在环的**辐射**上，不改反射率。
允许范围由量测的离散度界定：同帧比较环与行星盘时，带状平均、24 角表与逐带覆盖度带来约 ±20%，
系数落在其中就仍在模型自身的不确定度里。取在下沿是因为受光面在默认取景下比行星盘本身还亮。
屏上读数：B 环带平均 69.5 → 61.7 / 255。

## 过程中的两次更正（都记下来，避免重踩）

1. 第一版量测把 I/F 写成 `albedo·mu0/π`，又用了整图平均反照率，得出「环被压到 0.16、需要亮 5–6 倍」——**错**。
2. 第二版改用反解 ACES，行星盘读数比真实值高约 2 倍，于是得出「行星盘偏亮 1.4 倍」——也**错**。
   ACES 反解在这些电平上不可靠，这正是上面改用关闭色调映射一帧的原因。

### 那 1.4 倍当时排除掉的清单（保留作检索用）

| 假设 | 检验 | 结论 |
| --- | --- | --- |
| 采样的贴图不是应用渲染的那张 | 快照 `textureWidth` = 4096，正是 `8k_saturn.jpg`；换 `2k_saturn.jpg` 结果不变 | 排除 |
| 贴图色彩空间处理不同 | 基础贴图标为 sRGB，three 在采样时解码；按线性处理反而把偏差从 1.17 拉到 0.98 | 排除 |
| 光源强度语义与假设不同 | `WebGLLights.js:375` 把 `color × intensity` 当辐照度，`decay=0` 无距离衰减 | 排除 |
| 环境光 | 0.085 × albedo / π ≈ 场景辐射的 3% | 只解释一小部分 |
| 高光项 | roughness 1 + F0 0.04，几个百分点 | 只解释一小部分 |
| 镜头补光 | `keyLight`/`fillLight` 仅在 `__promoOffline` 下可见 | 排除 |
| 反解只对灰色成立 | 对暖色反解与真实亮度差 5% 以内 | 排除 |
| 程序云/活动层 | `gasMap` 在 `flowAmount=1` 时最多给反照率加约 6% | 不足以解释 |

## 工具与已知坑

- `photometry.mjs` 反解 ACES（`NO_TONE=1` 时退化为恒等）、按深度归属像素（谁在前谁被量）、
  两个面都能采。`shoot.mjs` 截图并写下一份几何/光照快照，支持 `TAG` / `DATE` / `OFFSET` / `BODIES`。
- `inspect-shadow-metric.mjs` 复现 `verify-saturn-shadows.mjs` 的正对取景并列出它标记为"被压暗"的像素，
  用来查那条形状断言为什么会读到 2.21 个半径（答案：它把 2–7/255 的量化噪声像素也算进去了）。
- 踩过的坑：`THREE.Vector3.copy(THREE.Color)` 读的是 `.x/.y/.z`，颜色上只有 `.r/.g/.b`，
  写进 uniform 就是三个 NaN；`addInitScript` 的回调要解构出参数，否则种子里传的值全是 undefined。
- `outputs/**/*.png` 在 `.gitignore` 里，图由上面的脚本重新生成；`*.json` 是每帧的几何/光照快照，进了版本库。

# 土星视觉检查 · 复现与回归

2026-09-13 的评审（见 [review.md](review.md)）用真实浏览器在桌面 1280 × 720 与手机 390 × 844 下记录了
三个缺陷。第 1 条（土星缺少扁率）已修完；第 2、3 条此后一直没有进入仓库文档，这个目录曾是它们唯一的记录。

2026-09-16 补上本目录缺失的可重跑脚本，并在当前 `main` 上重新检查第 2、3 条。结论：**两条都不再复现**，
且可以用像素量测说明为什么。

## 怎么跑

```bash
npx vite --host 127.0.0.1 --port 5311 --strictPort          # 别用已占用的端口，也不要让 Vite 回退
ATLAS_URL=http://127.0.0.1:5311 node outputs/saturn-review-20260913/verify-framing.mjs
```

写两份产物：`framing-report.json`（全部数字）与命名带日期的截图。**脚本不会写入 `desktop.png` 与
`mobile.png`**——那是 2026-09-13 的记录，复现时另存 `desktop-20260916.png`、`mobile-20260916.png`。

## 方法

界面是否挡住环，是像素问题不是几何问题，所以同一页面状态读两遍，都只裁画布：

- **场景**：把所有非画布元素设成 `visibility: hidden`（不触发布局重排，因此画面仍是渲染器画出来的那张），
  用来得到"渲染器画了什么"。
- **合成**：界面按原样，用来得到"访问者看到什么"。

某像素在场景里是亮的、在合成里仍高于可见下限（25），算**被压暗**；低于该下限才算**被遮住**。
只有后者是缺陷——底部栏顶边是 61% 透明度的渐变，压暗是它保证文字可读的方式。每个被遮像素再用
`elementFromPoint` 问一次当前文档，由报告直接说出是谁盖的，而不是靠猜；被场景锚定的标记名称标签
（`pointer-events: none`）按几何归属回内容。参考物取最大的连通亮区（土星受光圆面），这样别处的
零星亮点不会改变基准，并且**所看天体轮廓内的被遮像素数恒为 0** 是脚本的硬断言。自检把一块
**与评审当年量到的尺寸相同（255 × 215 px）的面板**放在旧面板所在位置，若指标没有牙齿就会漏掉它。

三档亮度阈值（60 / 90 / 140）同时报告，因为环的外侧比内侧暗，单一阈值可能把被遮区域当成背景。
测量在 `reducedMotion: 'reduce'` 下进行，与仓库其它浏览器验收一致；两次场景读取的差集为 0 px，
说明下面的数字不含动画干扰。

## 2026-09-16 结果

| | 桌面 1280×720 | 手机 390×844 |
| --- | --- | --- |
| 受光圆面最右缘 | x = 863 | x = 243 |
| 到最近固定界面的距离 | 153 px（底部目录 土卫六） | 119 px（天体资料与活动） |
| 场景亮像素 | 20,006 | 7,944 |
| 被固定界面压暗（仍可见） | 1,039 px，压到原亮度的 0.19–0.99 | 1,068 px，压到 0.12–0.60 |
| 被固定界面遮住（低于可见下限 25） | 11 px，其中天体轮廓内 **0 px** | 39 px，其中天体轮廓内 **0 px** |
| 自检：种下的 255×215 面板 | 遮住 12,673 px，判定成立 | 遮住 7,330 px，判定成立 |

- **第 2 条（右侧面板挡住环右端）不复现。** 右侧已无常驻控制面板，环右端与受光圆面的右侧都是空的。
  自检证明这套断言抓得住当年的原缺陷：同尺寸面板放在当年位置会遮住一万两千多个亮像素；现在那个位置
  是空白天空。
- **第 3 条（"动态活动"逐字竖排、工具栏压住环右端并延伸到下方信息卡）不复现。** 两个视口里每个已绘制
  控件的标签都是 **1 行**，没有控件越出视口，文档也没有横向溢出。旧症状之所以不可能重演：「动态活动」
  已不是常驻工具按钮，而是 `显示设置` 面板里的 `#activity-toggle`（标签「动态活动 · 开」），默认关闭。

2026-09-16 复核残留时改正了一处此前的判断。原先记录的"底部时间栏与资料卡裁到小卫星 97 / 45 px"
是按"合成画面里变暗"一律计为遮挡得出的，把**压暗**与**遮住**混在了一起。分开量之后：

- 桌面那 97 px 全部仍在原亮度的 38%–65%，清晰可见——底部栏顶边是 61% 透明度的渐变
  （`.explorer-bottom` 的 `linear-gradient`），压暗是它让文字可读的方式，不是遮挡。
- 低于可见下限的像素桌面只有 11 px（其中 7 px 归属到画布，实为场景内标记名称标签的投影，
  该标签 `pointer-events: none`，命中测试落到画布上），手机 39 px，其中 36 px 落在资料卡与
  天体名称的不透明底上。
- 三档阈值下**所看天体的轮廓都没有被固定界面覆盖（0 px）**，脚本现在把这条做成断言，
  并把"单个固定元素遮挡不超过 64 px"作为上限（当年那块面板遮了约 12,700 px）。
- 另有场景内标记「土星环阴影」的名称标签压住圆面 903 / 984 px，那是设计如此（标记随天体姿态
  定位于表面），按"场景锚定内容"单独归类，不计入固定界面。

## 证据与边界

- 命名带日期的截图由本脚本生成，按 [.gitignore](../../.gitignore) 只留脚本、`framing-report.json` 与本说明进版本库。
- 覆盖面只有默认土星近景这一取景。评审第 4 条列出的其它视角（斜侧、接近侧视）与环倾角、贴图、
  前后遮挡等专项仍未复核，见 [TODO](../../TODO.md) 的「土星其余视角专项复核」。
- 单次运行的绝对像素数会随视口、DPR 与天体姿态变化；可比的是"有没有被界面盖住"这一判断，
  以及自检与实际遮挡量之间的量级差。

# 行星投在环上的影：量纲修正的证据

用户看图指出环上的黑色区域过大，应该只投在背阳侧的一块。修在 `solar-system/src/dynamics.js`
的 `planetTransmission`（缩放极向分量、不再除天体半径）与调用处。这里留的是定位用的脚本与截图，
不是发布验收的一部分——验收记录在 [RELEASE_ACCEPTANCE.md](../../RELEASE_ACCEPTANCE.md)。

## 怎么定位的

两件事一起看才说得清：影是"投在环上"，所以要在**正对极轴**的取景里看它的平面形状——
相机放在北极轴向外 11 倍半径处，环面与光轴垂直，屏幕坐标就是环面坐标（行星本体的投影半径当尺子，
不需要重建环网格的坐标系）。`shoot-pole.mjs` 就是这个取景，三个日期各拍投影开、关两帧：

```bash
npm run dev                       # 或任意开发服务器
ATLAS_URL=http://127.0.0.1:5173 node shoot-pole.mjs
node measure-band.mjs
```

- `faceon-<date>-on/off.png` — 正对极轴的成对截图，`faceon.json` 记下每个取景的相机、朝向与太阳方向。
- `measure-band.mjs` — 用行星投影像素半径做标尺，量影沿太阳面内轴与垂轴的分布，并与解析值对照：
  太阳在环面仰角 e 时，影是 `a²(1 − cos²e/|s′|²) + b² < 1`（`s′` 为按 1/扁率缩放极向后的太阳方向），
  即横向半宽恰为 1 个赤道半径、背阳向长度 `1/√(1 − cos²e/|s′|²)` 的舌形，且只有背阳那一半。
- `shoot-default-view.mjs` — 用户报的那类取景（目录里点土星、默认相机、开活动层），三个日期各一对。
- `before-*.png` 与 `default-*-on.png` 是同一天同取景的修前/修后截图，`crop-*.png` 是裁切并提亮的对照。

## 读到什么

| 量 | 修前 | 修后 | 解析预期 |
| --- | --- | --- | --- |
| 影的横向半宽（2002 至点，正对极轴） | 2.18 个赤道半径 | 0.77 | ≤ 1.00（行星本体遮住 1.05 以内，故实测偏小） |
| 环面被压暗超过 10% 的像素 | 56,405 | 7,715 | — |
| 背阳侧之外的暗像素 | 0 | 0 | 0 |
| 背阳向延伸（2002 至点） | 被上一条错误淹没 | 2.05 个赤道半径 | 2.05（不压扁则 2.22） |

2.18 就是被多除的天体半径倍数：环网格按赤道半径归一化（顶点半径 = km / 赤道半径），
再除一次 `uBodyRadius` 会把每个环面点缩进行星半径以内，本影判据于是退化成"这个点在不在背阳侧"。

## 修前/修后怎么生成的

截图脚本本身不切换实现。修前那一组是把 `solar-system/src/dynamics.js` 用 `git checkout` 还原到改动前拍完再改回来，
所以 `before-*.png` 对应的是分支上一个提交的渲染，不是另一套代码。

# 环的两个面：受光面与背光面

用户要求"被照到的面偏亮，另一面偏暗"。改动在 `solar-system/src/dynamics.js`：环面着色器过去把太阳方向与环法线夹角的
绝对值当入射余弦，两面共用反射解；现在按两个余弦的符号判面，背光面改用同一张散射表的透射解。
这里留的是定位与量测用的脚本与截图，验收记录在 [RELEASE_ACCEPTANCE.md](../../RELEASE_ACCEPTANCE.md)。

## 为什么不用新表

Chandrasekhar 的有限大气解里，透射与反射共用同一对谱因子：

    R(mu,mu0) = mu0/(mu+mu0) · [X(mu)X(mu0) − Y(mu)Y(mu0)]
    T(mu,mu0) = mu0/(mu−mu0) · [X(mu)Y(mu0) − Y(mu)X(mu0)]

`ring-scattering.json` 存的是前者的秩二分解，于是背光面可以直接从同一张纹理读出来。
`check-transmission.mjs` 验证这条恒等式并给出逐环区的对照；`survey-faces.mjs` 把它压缩成一张表
（太阳 mu0 = 0.604、视线 mu = 0.354）：

| tau | 反照率 | 受光面 | 解算器背光面 | 背光/受光 | 从发货表读出的背光面 |
| --- | --- | --- | --- | --- | --- |
| 0.031 | 0.1 | 0.0021 | 2.03e-3 | 98% | 2.08e-3（100%） |
| 0.147 | 0.1 | 0.0078 | 7.44e-3 | 96% | 7.64e-3（98%） |
| 0.687 | 0.5 | 0.0985 | 7.22e-2 | 73% | 7.41e-2（75%） |
| 1.231 | 0.5 | 0.108 | 4.81e-2 | 45% | 4.94e-2（46%） |
| 3.144 | 0.6 | 0.145 | 8.70e-3 | 6.0% | 7.85e-3（5.4%） |
| 5.441 | 0.6 | 0.145 | 8.21e-4 | 0.57% | 1.91e-3（1.3%） |
| 8.312 | 0.6 | 0.145 | 5.40e-5 | 0.04% | 1.88e-3（1.3%） |

薄的环两面几乎一样亮，厚的环背光面近乎全黑；重构在 tau ≤ 3 时与解算器基本一致，最厚的几区偏亮，
但那里两者都不到受光面的 1.3%。`ship-residual.mjs` 给出全环区的残差分布：tau ≤ 1 相对误差 16% 以内，
所有环区相对受光面 12% 以内。残差由 `solar-system/tests/ring-multiple-scattering.test.js` 的两条界限钉住。

```bash
npx tsx check-transmission.mjs     # 恒等式与逐角对照
npx tsx ship-residual.mjs          # 限定到实际发货表的残差分布
npx tsx survey-faces.mjs           # 上表
```

## 怎么量的

`shoot-faces.mjs` 把相机放在极轴 11 倍半径处（环面与光轴垂直，行星投影像素半径就是尺子），
南极、北极各拍一张：同一天里一张是受光面、一张是背光面，角度相同，差的就是"哪一面"。

```bash
npm run dev
ATLAS_URL=http://127.0.0.1:5173 node shoot-faces.mjs
node measure-faces.mjs             # 按环带（C/B/卡西尼/A）分别给两面的线性亮度
npx tsx check-bands.mjs            # 与同一模型的解析值对照
```

- `face-<date>-<pole>[-noshadow].png`、`faces.json` — 成对截图与取景几何。
- `measure-faces.mjs` — 两面的逐带亮度；2002 至点：C 环 93%、卡西尼缝 64%、A 环 55%、B 环 18%（受光面为 100%）。
- `check-bands.mjs` — 窄径向带与模型对照（模型 = 着色器同一套公式）：A 环模型 0.535 对像素 0.497；
  B 环两侧都近全黑（模型 0.008、像素 0.012）；C 环太暗（约 1/255），像素读不出，量的是背景。
- `shoot-underside.mjs`、`shoot-default.mjs` — 应用自己的取景，上下两侧与默认视角；`side-before-*.png` 与
  `side-faces-*.png` 是同一天同取景的改前/改后对照（改前那条环在背光面也是亮的）。

## 读到什么

| 量（2002 至点，正对极轴） | 改前 | 改后 |
| --- | --- | --- |
| 背光面/受光面亮度比 · B 环 | 54.1% | 8.9% |
| 背光面/受光面亮度比 · A 环 | 58.6% | 51.1% |

改前两个数都被拉平到一半上下，正是因为两面用了同一个解；改后薄的 A 环透射得多、厚的 B 环近乎全黑，
差出一个数量级——这是环的厚度差异在背光面上的直接体现。

## 改前/改后怎么生成的

截图脚本不切换实现：`before-*` 是先用 `git stash` 把 `dynamics.js` 还原到改动前拍的，拍完恢复。

`outputs/**/*.png`、`*.jpg` 在 `.gitignore` 里，图由上面的脚本重新生成。

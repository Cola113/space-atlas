# 十九个落点的科学与绘制校核

2026-09-14 建立，2026-09-16 随落点增至十七处重建，2026-09-19 加入谷神星，2026-09-25 加入地球·冒纳凯阿。这里记录已取得的证据与限制；完整项目的性能、全站交互与发布验收仍在进行。

## 独立参考

`scripts/build-ground-audit.mjs` / `.py` 生成 749 个样本，覆盖全部十九处落点；同一天体的第二落点各有自己的样本，样本以落点 id 为键，天体 id 单独保留（独立位置按天体算，观察几何按落点算）。每个落点均含 1900 年起点、年末、1971、J2000、2100 年末及四个轨道周期内每周期八个间隔采样。太阳和主星位置来自 [DE440s](https://naif.jpl.nasa.gov/pub/naif/generic_kernels/spk/planets/de440s.bsp)、原始 SAT441/URA184/PLU060 记录，以及 [Horizons](https://ssd-api.jpl.nasa.gov/doc/horizons.html) 返回的木卫一、木卫二、木星几何 ICRF 向量。每个木星系统目标包含 136 个独立历元，分三次请求取得——Horizons 单次最多返回 80 个离散历元且会静默截断，接口也拒收长 TLIST 的查询串，因此按 60 个历元一批用 POST 取回，每批的查询与响应摘要分别留在参考文件里。谷神星不在 DE440s 中，参考侧改由 CSPICE 直接解算 Horizons 生成的 SPK（目标 20000001）。这仍然把**随站发布的 Chebyshev 年份包**与源文件分开——解码或窗口切分错误会表现为整个天空级的偏差——但它与发布版同源，因此只证明表示与实现正确，不构成对它的独立轨道解；其紧档数值（太阳方向 0.0001 角分）应这样解读。地球落点额外带月亮的独立样本（同样出自 DE440s）：赏月落点的核心天体不能只靠太阳样本间接覆盖。

CSPICE 独立计算 [PCK00011](https://naif.jpl.nasa.gov/pub/naif/generic_kernels/pck/pck00011.tpc) 姿态、球面观察位置、局部东/天顶/北坐标及相位。参考与应用均未加光行时、像差和折射；这核验几何模型而非望远镜同期视位置。火星以系统质心代替中心，卫星造成的中心差小于 0.2 m。输入 TT/TDB 使用另有测试的时间层；未来闰秒与早期时间近似没有因此消失。

文件哈希、Horizons 查询及响应头存入 `tests/ground-audit-reference.json`。测试离线运行；原始 SPK、HTML 和完整 API 响应保存在忽略的 `data/` 中。重新生成需要本节列出的四个内核放在 `data/jpl/`、`data/ephemeris-tools/` 下有 numpy/spiceypy/jplephem 的 Python 环境，然后运行 `npx tsx scripts/build-ground-audit.mjs --download`，它只下载缺少的 Horizons 查询。三个系统切片可由 `build-ephemeris.py --download-only` 以 HTTP 范围请求从 NAIF 抽取，不需要整卷下载；本次重建得到的切片与 PCK、DE440s 的 SHA256 与上一轮记录逐一相同。

地球一行的数值量级与其余各行不同，原因在观察者框架而不是天体位置：太阳与月亮的方向差几乎相同（J2000 附近 2.6 角分，1900 年约 5.1 角分，2100 年 14.3 角分），说明差异来自观察者本地框架的自转相位——应用侧地球姿态用 Astronomy Engine 的 GAST（真赤道与分点，含岁差章动，UT1 以 UTC 近似），参考侧用 PCK00011 的 IAU_EARTH 多项式按 TDB 采样，两个独立实现的地球定向在本征上就差这个量级，而且都各自标注了不能用于精密地球定向。该落点的方向门槛因此放宽到 16 角分（太阳与月亮同档），入射光方向同样在本地框架内表达，同档；受光比例不受框架旋转影响，仍取 0.001 的严格档。这不是把误差当成通过：它是两个合格实现之间的已知分歧，写入门槛并在此说明。

## 遮挡及实际绘制

独立 CSPICE 找到土卫二上 2026-09-13 的一次土星日食出影，并在 14:32:36.536 UTC 附近以九个时刻采样。太阳面采用 131072 条射线与主星球面轮廓相交来估算可见比例，不复用浏览器的圆相交公式。本批最大可见比例差约 0.0440（4.40 个百分点），来自太阳日心模型差等因素；这不是精密接触时刻预报。

运行时遮挡使用均匀亮度圆面、实际距离和角尺度，不含临边昏暗、折射、扁球轮廓或完整土星环透射。多个圆面重叠时对遮挡面积取并集，避免重复扣光。增加火星自身卫星及冥王星其它卫星的天空节点；火卫一、火卫二等仍采用有来源的平均轨道，其凌日不能解读为真实日期预报。太阳、主星及其它球体保持紧凑显示坐标和真实角大小，但每个片元以恢复后的真实视深写入对数深度缓冲；环、云层和太阳光晕共用这套深度。只排序压缩后的球心会把前景小卫星埋进主星显示球体，该问题已用像素测试复现并修正。地形、天体与远方星空分配不同深度区间，地球薄云层仍保留多个 24 位深度级别。

`scripts/verify-ground-rendering.mjs` 使用实际 `SurfaceSky` 材质，针对七个有主星的落点各取三个相位，以 WebGL 像素回读比较独立参考的向阳/背阳区域；另用已知前后关系的物理位置检查太阳前后遮挡、主星前方凌星与后方掩星的中心像素，并检查火星/冥王星卫星节点。这项受控测试采用白色纹理并隐藏地形、大气，以隔离光照与深度问题；不能代替成品纹理、大气及 UI 验收。报告及截图位于 `test-results/ground-rendering/`。成品四屏、浓雾、山体、望远镜、暂停与返回继续由 `scripts/verify-landings.mjs` 检查。

## 2026-09-16 新落点的覆盖范围（已补齐）

同一星球现在可以有多个落点，落点总数由九处增至十六处。七处新落点在本轮纳入独立对照，原先"独立对照只覆盖原有九处"的限制不再成立：

- 参考文件重建为 632 个样本、十六处落点；同日稍后又随金星落点增至 671 个样本、十七处，2026-09-19 随谷神星落点增至 710 个样本、十八处，2026-09-25 随地球落点增至 749 个样本、十九处；新落点同样先有样本才允许登记。`fixtures` 每条带 `siteId`，天体 id 单独保留；构建器与测试都改为按落点取值。测试改为断言**每个落点都有样本**——新增落点而没补样本会直接失败，原来的"九个不同天体"计数断言做不到这一点。
- 重建使用与上一轮相同的内核。DE440s、PCK00011、由 SAT441/URA184/PLU060 抽出的三个切片，以及由这些记录重打包的 coverage SPK，六个文件的 SHA256 与上一轮记录逐一相同；原有九处的 359 条样本重算后 357 条逐位相同、2 条相差 3.5e-13 弧度（浮点末位）。
- 木星系统目标的历元数由 71 增至 136，超过 Horizons 单次返回 80 个离散历元的上限（超出部分会被静默截断），且长 TLIST 的查询串会被前端以 502 拒绝；现按每批 60 个历元用 POST 取回，每批的查询与响应摘要分别记录。
- 新增落点的最大角差与相位差见上文两张表，与同天体原有落点同量级（次木星点 3.74 对木卫一 3.73 角分，月背 1.37 对月球 1.38 角分）。冥卫一的主星是冥王星、位置同出自 JPL 内核，已并入紧档 0.001 角分。
- 落点几何的浏览器成品侧检查仍走 `scripts/verify-landings.mjs`（十九处 × 四屏），与旧落点同一标准。
- 2026-09-19 的谷神星是这批里第一个**参考与应用同源**的条目：它不在 DE440s 里，参考侧只能用同一份 Horizons SPK。因此它在表里的 0.0001 角分证明的是年份包解码与窗口切分没错，不构成独立轨道解，与其余十七行的证据等级不同；若日后有第三方谷神星历可作对照，应替换本条参考。

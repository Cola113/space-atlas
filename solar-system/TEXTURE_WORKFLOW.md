# 星空图鉴贴图生成与接入

本页维护本项目的球面贴图要求、提示词、后处理与接入验收。通用生图 skill 只负责生成/编辑接口、尺寸、批量、鉴权和失败恢复；调用时由项目提供本页要求。

2026-09-12 用户要求善用文生图、图生图、多图参考与提示词，已记录于项目 [AGENTS.md](../AGENTS.md)。当前默认模型 `gpt-image-2.5-sunburst`，明确传 `quality: high`；下文旧 `gpt-image-2` 尺寸记录只代表当次结果。落地全景与行星全球 albedo 的投影用途不同，最新七个落点的生成、参考合成和验收见 [表面观景来源](../public/surface/README.md)。

本项目当前采用艺术完成度优先的地表方案，缺失地貌可以整体重绘；这不表示新增观测，也不应成为其它项目的默认。已交付记录见 [贴图导入记录](TEXTURE_IMPORTS.md)、[艺术地表说明](../public/solar-system/textures/artistic/README.md)。

## 先确认图片承担什么作用

先读项目实际使用的贴图路径、映射方式和材质代码，查看现有图片与尺寸。区分真实缺测、低分辨率、程序化占位、正常暗色地表和场景夜侧；不要把正确的夜半球当作空白贴图。

用户允许完整艺术重绘时，可将黑色缺测和模糊占位当作待补全区域，提示词说明原图只提供身份、色调或地貌词汇。必须保留观测地貌时，参考图编辑并不等于原像素保留；需要保护的区域通过遮罩合成回原图并核对差异，说明遮罩是视觉选择而非完整科学覆盖图。缺少可用原图的天体可以文生图，交付注明艺术构建。

贴图负责表面颜色/材质。环、赤道隆起、非球形轮廓、轨道与自转应由几何或程序实现；平面 albedo 图中不画独立星环、球体轮廓、背景星空或晨昏线。如果发现这些结构遗漏，说明并在项目任务范围内处理，不能声称更换图片已经修好。

## 2:1 球面地图提示词示例

根据对象和用户风格改写，不将“艺术优先”固定为所有请求的默认。

```text
用途：交互式 3D 天体的完整全球 albedo 贴图。
主体与风格：[对象、材质、主要颜色、尺度不同的地貌；用户是否允许艺术构建]。
参考图：[若有：第几张图片提供什么参考、哪些区域要保留、是否允许整体重绘]。
投影：单张平面 2:1 等距圆柱经纬图，北极在上、南极在下，赤道居中。
构图：全画布由地表覆盖，横向 360°；左右地貌与颜色连续，极区适合球面收敛。
照明：均匀漫射的表面颜色，不烘焙全球定向光、反光、晨昏线或投影。
细节：大尺度地貌、区域变化与细微纹理都完整，避免重复克隆、过锐噪点和矩形拼块。
避免：球体渲染图、地平线、宇宙背景、星环、边框、标签、网格、水印、黑色缺测块。
尺寸：3840 × 1920（按任务要求调整；实际返回尺寸必须检查）。
```

2026-09-12 使用八方 `gpt-image-2` 请求 `3840x1920`，成功结果返回同尺寸。服务商文档仍说自定义尺寸可能对齐档位，此处是项目实测，不能保证后续请求都一样。八方 CLI 的 `--aspect-ratio` 没有 `2:1`，需传自定义 `--size`，例如：

```powershell
# $imageCli 指向已安装的 bafang-imagegen/scripts/image_gen.py。
python $imageCli generate --prompt-file work/imagegen/terrain.txt --size 3840x1920 --out outputs/terrain.png --dry-run
python $imageCli edit --image source-map.png --prompt-file work/imagegen/repaint.txt --size 3840x1920 --out outputs/repainted-map.png --dry-run
```

按用户已授权的生成范围执行时去掉 `--dry-run`。若实际宽高改变，先检查并处理适配，不能将宽屏图直接拉伸成经纬图或为凑“4096”擅自放大。

## 本地处理与验收

- 保留未经修改的生成原图；修缝、极点处理、压缩后的版本另存。记录每一步尺寸，不能把插值放大写成原生生成。
- 先检查原图全幅和局部，再做球面或实际项目渲染，至少检查正面、背面、左右接缝与两极。左右边缘像素相等只能证明边界数值接上，不能证明附近地貌自然连续。
- 必要时用窄带平滑混合处理经度接缝、以渐变收敛处理极区。带宽随素材决定；单纯按行向内延伸颜色偏移可能产生横向拖痕。修复后再次检查整圈，避免制造镜像纹、模糊带或极点辐射纹。
- 完整度与锐度分开判断：黑色/低亮度网格检测可帮助找大块缺测，但阈值应随材质选择，深色岩石或陨坑不能一律判错。检查模糊空白、过曝白块和重复结构。
- 在实际材质与昼侧视角下确认可读细节；使用正确经度循环采样。暗半球的亮度不是贴图是否成功的判据。
- 近景可用原尺寸无损 WebP，概览可用缩小的有损 WebP，按项目加载性能和内存取舍。无损只表示相对处理后的像素没有编码损失，不表示等同于原始观测或未经过修缝。
- 批量逐项核对稳定 ID、中文/英文名称、原图、生成方式、基础/高清路径和实际像素。保留成功项，失败项进入恢复流程；不要因为别名或编号有误而重新生成整批。
- 项目接入后检查所有引用可读、近景确实换用高清、缓存上限符合项目约束、手机不卡死；画面以实际浏览器截图为准。生图成功不等于代码接入完成。

现有加工脚本是 [`scripts/prepare-artistic-textures.py`](../scripts/prepare-artistic-textures.py)，读取已保存 PNG，不调用生图 API；依赖 Pillow 和 NumPy。清单含 `id` 与可选 `reference`，输入文件按 `<id>.png` 命名，脚本接受实际尺寸 3840 × 1920。经度带和极区带当前分别为宽度的 3.5% 和高度的 2.5%；这些是本批素材参数，不是通用标准。重新运行前先核对清单和已有资产，必要时用 `--skip-existing` 保留哈希一致的结果。

## 交付记录

项目公开记录可包含稳定 ID、文生图/参考图重绘、生成/交付尺寸、处理方式、文件哈希、素材来源和艺术/观测范围说明。私有记录保留完整请求、响应与重试对应关系；公开文件不带凭据、本机绝对路径、临时签名链接或原始 API 响应。

描述方式举例：“2 张参考图整体重绘，26 张文生图；实际生成 3840 × 1920，概览降采样为 1920 × 960，近景保留原尺寸并做修缝。”数量按本次记录统计。不能将混合流程统称为无损超分，也不能把新增艺术细节当作观测细节。
